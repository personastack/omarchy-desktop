# cuamcp

`cuamcp` owns one Linux `cua-driver mcp` stdio process. Cua Driver 0.30.1 documents that this process owns the Linux runtime directly unless a socket is explicitly supplied. PersonaStack supplies no socket, so it does not discover, start, attach to, or stop an ambient Cua daemon. The companion supervises and stops only the child process it starts. This is the Linux no-autospawn path. It does not need a separate socket or peer-identity protocol.

The client negotiates MCP `2025-06-18`, the initialization revision documented for Cua Driver 0.30.1, then uses bounded newline-delimited JSON-RPC. It validates response IDs and MCP result envelopes, validates the catalog against the macOS app's reviewed 33-tool allowlist, serializes calls, pins the owned child to Cua's `standard` permission mode, and disables telemetry and update checks in the child environment. The parent process environment cannot change the selected mode. PersonaStack still authorizes each remote operation through its existing installation, workspace, persona, and lease checks. Timed-out writes terminate the owned child so a blocked pipe cannot hold shutdown. Setup can request Cua's Linux `health_report` or its read-only `check_permissions` result. `ReadyFor("0.30.1")` means the schema-version-1 diagnostic report matches that selected driver version, reports `overall: ok`, and passes `binary_version`, `platform_supported`, `session_active`, `ax_capability`, and `screen_capture_capability`. These checks do not establish an unlocked interactive desktop or prove that a screenshot was captured. Linux capture capability can use compositor protocols beyond X11. Neither setup method is available through remote Desktop Control operations. The executable path must come from the integrity-checked Cua installation owner. This package does not install Cua or claim that a tool works on Hyprland/Omarchy.

The process choice follows Cua's pinned [0.30.1 process model](https://github.com/trycua/cua/blob/cua-driver-rs-v0.30.1/docs/content/docs/reference/cua-driver/process-model.mdx). Native acceptance on the supported Omarchy profile remains required.
