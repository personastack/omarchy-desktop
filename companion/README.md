# Go companion

The companion owns PersonaStack machine credentials, enrollment and gateway transport, Cua integration, local CLI setup, and bounded filesystem and process execution.

`cmd/personastack-companion` is a newline-delimited JSON process scoped to one configured app origin. The Desktop Control bridge supports `sync`, `state`, `prepare`, `pause`, `resume`, and native-only `disconnect`. Pause state is stored per origin in a private user config file. A saved pause prevents automatic runtime recovery after restart. Resume requires an active API relay and an unlocked Hyprland session. Disconnect pauses and fences local execution, revokes all installation mappings through the producer API client, then removes the protected credential. A failed revoke retains the credential and paused runtime for retry. The local-session bridge supports its versioned state, harness selection, prepare, and configure commands through the Linux CLI probe and plugin installer.

Machine credentials stay in the Linux Secret Service adapter and never appear in process arguments, bridge logs, or replies. The hosted bridge accepts commands only from the registered main frame at the configured origin and current document generation. Electron builds the companion into `companion/bin` for development and starts it lazily. The local Arch recipe installs it at `resources/bin/personastack-companion` for packaged launches. The recipe is not a published release package.

The integrated lifecycle prepares the pinned Cua runtime, enrolls or attaches through the producer-owned API client, creates the authorized executor, monitors the Hyprland lock state, and connects the Gateway. Gateway owns API session preparation and claim. The client reports ready only after a fresh Gateway heartbeat acknowledgement. On socket disconnect, the executor is fenced before reconnect. The reconnect loop restores idle relay resources only after an API status read proves an active relay remains. Explicit user pause is separate from idle resource cleanup. Pause reports the API's existing `paused` readiness, fences execution, stops Cua, and keeps the saved preference. Resume validates active enrollment and an unlocked session before restoring runtime readiness. Explicit disconnect prevents reconnect, fences execution, pauses Cua, revokes the installation and closes Gateway on success. API failure leaves the credential and Gateway available for a paused retry.

The Cua installer downloads the Linux x86_64 candidate from `support-profile.json`, checks published archive and extracted file hashes, and preserves the Cua MIT and Node runtime MPL-2.0 notices. It installs under the user's data directory. `internal/desktopgateway` and `internal/cuamcp` implement bounded transports. `internal/desktopexecutor` implements the reviewed Cua dispatch families, bounded screenshot results, exclusive lease, and revocation fences. With `NewWithLocalOperations`, it routes file and managed-process calls through the same scope and lease checks. `internal/desktoplocal` maps producer operation DTOs to bounded file and process managers and closes their handles on lease release or scoped revocation. Local-session setup validates the producer-owned bundle, checks the selected CLI, and writes only PersonaStack-owned plugin files.

Tests use fake APIs, commands, sockets, download responses, an MCP child process, and temporary files. The Linux installer also passed against Codex CLI 0.157.1 and Claude Code 2.1.152 in disposable profiles. That check covered plugin installation, marketplace and cache readback, and preservation of unrelated profile settings. It does not prove authenticated provider or MCP connectivity, Secret Service, Cua, Gateway authorization, tray behavior, or Omarchy behavior. The optional Hyprland input plugin is not installed. There is no plaintext credential fallback. Keep API and Gateway wire contracts imported from their producer-owned Go packages.

The module requires Go 1.27.0 and suggests Go 1.27.1. Select the pinned toolchain with `GOTOOLCHAIN=go1.27.1`. The `personastack-api/pkg/client` dependency is private, so Go validation requires configured Git access or a temporary local replacement with the exact producer-owned client revision.
