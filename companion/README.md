# Go companion

This module will own PersonaStack machine credentials, enrollment and gateway transport, Cua integration, local CLI setup, and bounded filesystem and process execution.

`cmd/personastack-companion` runs the Go companion as a newline-delimited JSON process. It accepts a single production or LAN app origin argument. The Desktop Control bridge supports `sync`, `state`, and `prepare`. `prepare` reports that the Linux runtime is unavailable, so it does not consume an enrollment ticket or claim Desktop Control readiness. The local-session bridge supports its versioned state, harness selection, prepare, and configure commands through the Linux CLI probe and plugin installer. Machine credentials stay in the Linux Secret Service adapter and never appear in process arguments, bridge logs, or replies. `npm start` builds it into `companion/bin` and Electron starts it lazily for a request from the registered main frame at the configured origin and current document generation. Packaged app bundling is not configured yet.

Host-independent packages also prepare, claim, heartbeat, and report session readiness through the producer-owned API client. Local-session setup validates the producer-owned bundle, checks the selected CLI and writes only PersonaStack-owned plugin files. Tests use fake APIs and commands. There is no plaintext credential fallback. These tests do not prove real API, CLI plugin-manager, or Secret Service behavior on Omarchy. Keep API and gateway wire contracts imported from their producer-owned Go packages.

`go.mod` requires Go 1.27.0 and suggests Go 1.27.1. Go may use a newer installed toolchain, so future companion validation must explicitly select the pinned toolchain with `GOTOOLCHAIN=go1.27.1` rather than treating the `toolchain` directive as an upper bound.
